# C10 tranche 1: mechanism reconciliation

This ledger classifies the mechanisms traced in the [ranked research audit](research.md)
and [supplemental caller audit](source_supplement.md) against the
[delivered results](tranche1_results.md). Exact source revisions, file hashes
and licenses are in the [source manifest](../../inputs/controls/c10_source_pins.json).
`Tested` refers to the named isolated arm and regime; it never rejects every
implementation of a broader mechanism. `Equivalent` means the specified v2
mechanism already exists, not that its settings are optimal. `Rejected` applies
only to a stated direct transfer or measured arm. `Handed off` preserves the
existing owner and does not claim a C10 implementation.

## Post-tranche source and outcome check

The pinned [Yamaquasi caller and `select_a`](https://github.com/remyoudompheng/yamaquasi/blob/3f95f43682ed15d8c1ed206a9a702dd655d7c8ad/src/siqs.rs#L707-L842)
first generate more A products than needed, rank by exact distance to the
target and truncate, then sort the selected values numerically. For small
factor counts it enumerates combinations; the larger path samples cores and
corrects one prime. [FLINT's A initializer](https://github.com/flintlib/flint/blob/a4c9750d0d3d67bb01cf6d18c187591b313451c3/src/qsieve/compute_poly_data.c#L23-L50)
enumerates small-factor combinations or selects a corrective factor for
lexicographic cores inside a target window. [CUDA-MPQS](https://github.com/drjanosch42/cuda-mpqs/blob/99c61967585b97a71b28fbaf19690af83ac88c17/src/sieve/prime_algorithms.cu#L711-L775)
starts from an actual-product window and subsequently exchanges neighboring
prime indices. [Kechlibar's implementation paper](https://www.karlin.mff.cuni.cz/~krypto/Implementace_MPQS_SIQS_files/main_file.pdf),
§2.3.8–10, separately discusses unique A values and their quality. None of
these paths establishes that sorting *the same fixed 16 families* nearest
first should improve complete factors. The C10 quality arm tested only that
narrow ordering, not their pool/window selection or independent overlap
control; these remain C10a-02.

The plan arm likewise tests v2's bounded per-polynomial power-mark reuse, not
the native root-transition, bucket or GPU batch implementations. At 30 digits
its 91,582 per-prime plans were replayed five times each, compared with 33
replays per plan at 40 and 50 digits. The 30-digit plan/control difference is
inconclusive under the frozen paired rule; the shorter reuse interval is a
supported amortization explanation, not a proven hardware-level cause.
Quality's 30-digit arm produced 411,862 additional candidates but 409,320
additional exact-refinement rejections, so greater early product proximity
did not translate into enough useful output in that tested order. These
counts and stage totals are in the [delivered result](tranche1_results.md).

No pinned upstream executable was run under the C10 matched protocol. Source
mechanisms explain what each implementation *does*, not a measured speed
ratio against v2 on identical inputs, parameters and hardware. This
reconciliation covers the nine pinned implementations and the named papers;
it does not claim every current SIQS implementation has been surveyed.
