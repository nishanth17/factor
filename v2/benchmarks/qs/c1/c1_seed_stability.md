# C1 confirmation: pre-generation seed-stability clarification

Frozen after training and before creating or inspecting the fresh corpus.
No runtime source, collector setting, workload, allowance, sample count,
extension trigger or bootstrap is changed. Preserve the original protocol
and report its pooled instability flags without reinterpretation.

The original rule mixes three deliberately different seeds in its IQR. A
large pooled spread can therefore describe repeatable seed-dependent work,
rather than measurement noise. Continue extending to18 and27 exactly as
specified when that pooled test fails. Do not discard seeds or samples.

For an input/arm that fails the pooled check, a secondary, predeclared
assessment is eligible only after27 samples, providing9 repeats of each
seed7/29/47. Within every seed stratum of that cell, require the same <=10%
relative IQR and <=10% first/last-third median drift. If any such stratum
fails or lacks9 samples, conditional stability is not established. Cells
that pass the original pooled rule retain that primary verdict. Report
pooled and within-seed results together.

Under the roadmap's revised policy, a class with pooled instability can be
considered only if every input/arm passes either its primary pooled rule or
this conditional fixed-seed rule, the original paired
bootstrap supports a positive complete-cost/completion effect, and the
observed capped-cost direction across both inputs is nonnegative for each
of the three seeds. This is a pre-confirmation analytical clarification,
not retrospective rescue of a failed held-out result. It does not relax
correctness, resource, uncertainty, regression or scope requirements, and
never establishes a default automatically. No additional experiment beyond
the existing27-sample /10,800-second ceiling is permitted.
